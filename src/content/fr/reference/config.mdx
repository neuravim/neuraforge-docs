# Référence configuration

> Cette référence publique couvre la configuration côté utilisateur. Les schémas internes détaillés restent dans la documentation interne.

## Configuration projet minimale

```yaml
project: my-project
provider: claude-code
mode: standard
lang: fr
```

## Clés courantes

| Clé | Objectif |
|---|---|
| `project` | Nomme le projet pour les artefacts et le suivi |
| `provider` | Définit le provider IA par défaut |
| `mode` | Sélectionne `flash`, `standard` ou `enterprise` |
| `lang` | Définit la langue des artefacts |
| `rules` | Pointe vers les règles d'équipe |
| `memory` | Active ou encadre la mémoire contextuelle |

## Préférences provider

NeuraForge peut fonctionner avec plusieurs providers. La configuration publique doit rester centrée sur le provider préféré et sur le type d'accès IA utilisé : local, cloud ou proxy enterprise.

```yaml
provider: claude-code
```

Pour l'authentification et l'installation par provider, consultez les guides providers.

## Mode de workflow

```yaml
mode: standard
```

- `flash` : petits changements à faible risque.
- `standard` : travail produit courant.
- `enterprise` : changements sensibles, réglementés ou critiques production.

## Règles et templates

```yaml
rules:
  - .neuraforge/rules/coding-standards.md
```

Les règles et templates rendent les attentes d'équipe explicites. Gardez les processus internes détaillés dans la documentation privée lorsqu'ils décrivent l'implémentation.

## Mémoire

```yaml
memory:
  enabled: true
```

La mémoire aide NeuraForge à réutiliser du contexte projet durable. Elle doit rester un guidage, pas la source de vérité.

## Standards enterprise

Les organisations peuvent définir des standards communs pour le mode, les providers, les validations, la sécurité, les tests et la documentation. Le schéma exact doit être géré en interne par l'équipe plateforme ou enablement.

## Aides CLI

```bash
neuraforge config show
neuraforge config set mode enterprise
neuraforge config get provider
```

## Frontière public/privé

La documentation publique évite volontairement d'exposer :

- schémas internes complets ;
- assemblage des prompts ;
- contrats de hooks ;
- détails d'orchestration ;
- algorithmes de routing provider ;
- seuils exacts des quality gates.

Pour ces détails, utilisez la documentation technique interne.
