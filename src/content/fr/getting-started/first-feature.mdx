# Votre première fonctionnalité en mode standard

> Le mode Standard sert aux vraies fonctionnalités : comprendre la demande, planifier le changement, implémenter, puis vérifier le résultat.

Ce tutoriel montre l'expérience utilisateur publique sans exposer les contrats internes d'orchestration de NeuraForge.

## Scénario

Ajouter un endpoint health-check à une API existante.

```bash
neuraforge standard "Add GET /health returning { status: 'ok' } with tests"
```

## Ce qui se passe

NeuraForge guide le changement dans un flux structuré :

1. **Discovery** — comprendre le dépôt et le comportement demandé.
2. **Planning** — définir le changement attendu et les critères d'acceptation.
3. **Implementation** — modifier le code et les tests.
4. **Review** — vérifier que le résultat correspond à l'intention et n'introduit pas de problème évident de qualité ou sécurité.

Les artefacts et contrats internes exacts relèvent de l'implémentation privée. Ce qui compte côté utilisateur : le travail est traçable et vérifiable.

## Ce que vous devez inspecter

Après le workflow, vérifiez :

- fichiers modifiés ;
- tests générés ou mis à jour ;
- couverture des critères d'acceptation ;
- notes sécurité éventuelles ;
- résumé final et prochaines étapes.

```bash
neuraforge status
```

Puis lancez les checks normaux du projet :

```bash
npm test
npm run build
```

Utilisez les commandes adaptées à votre stack.

## Si le résultat n'est pas suffisant

Vous pouvez préciser la demande ou utiliser un workflow plus robuste :

```bash
neuraforge standard "Improve the /health endpoint with readiness checks and tests"
```

Pour les changements sensibles en production, utilisez le mode Enterprise.
