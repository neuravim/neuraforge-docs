# Configuration

> NeuraForge fonctionne avec une petite configuration projet et permet aux équipes d'ajouter des standards quand elles en ont besoin.

## Configuration minimale

Pour la plupart des projets, il suffit de déclarer le projet, le provider préféré, le mode et la langue.

```yaml
project: my-project
provider: claude-code
mode: standard
lang: fr
```

Le démarrage reste léger, tout en laissant la possibilité d'ajouter plus de gouvernance ensuite.

## Niveaux de configuration

NeuraForge prend en charge plusieurs niveaux de configuration pour éviter les conflits entre préférences personnelles, projet et entreprise :

1. valeurs par défaut du produit ;
2. standards d'organisation ;
3. paramètres du projet ;
4. ajustements par fonctionnalité ;
5. options de ligne de commande.

Le comportement exact de merge et le schéma interne relèvent de l'implémentation privée. Côté utilisateur, la règle est simple : les choix locaux et explicites priment sur les valeurs générales.

## Ce que vous pouvez personnaliser

Les zones de personnalisation publiques sont :

- provider IA par défaut ;
- mode de workflow ;
- langue des artefacts ;
- règles d'équipe ;
- préférences provider ;
- budget et sécurité ;
- comportement mémoire ;
- attentes de validation enterprise.

## Configuration enterprise

Les équipes peuvent définir des standards communs une seule fois et les réutiliser sur plusieurs dépôts. Exemples :

- provider préféré ;
- mode par défaut ;
- validations attendues ;
- règles sécurité ;
- objectifs de couverture de tests ;
- conventions de commit ;
- exigences documentaires.

## Modifier via la CLI

```bash
neuraforge config set mode flash
neuraforge config show
```

Utilisez la CLI pour la configuration quotidienne. Gardez les standards d'organisation dans le guide interne de l'équipe.
