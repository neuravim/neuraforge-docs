# Gouvernance mémoire

> NeuraForge peut utiliser du contexte projet et session, mais l'état actuel du dépôt et la demande utilisateur restent prioritaires.

## Pourquoi la gouvernance mémoire compte

Les outils IA deviennent plus utiles lorsqu'ils retiennent du contexte, mais la mémoire peut aussi devenir obsolète. NeuraForge traite la mémoire comme un guidage, pas comme un remplacement de la lecture du code réel.

La mémoire aide pour :

- conventions projet récurrentes ;
- décisions d'architecture précédentes ;
- contraintes connues ;
- préférences d'équipe ;
- retours d'expérience.

## Modèle public sûr

NeuraForge sépare le contexte par portée et applique des règles de gouvernance pour éviter que des informations anciennes ou sensibles prennent le dessus sur la tâche actuelle.

Trois principes côté utilisateur :

1. le dépôt et la demande explicite sont la source de vérité ;
2. la mémoire doit être vérifiée avant d'être utilisée ;
3. les informations sensibles ne doivent pas être copiées dans les artefacts générés.

Le schéma mémoire interne, les sections de prompt, les règles de précédence et la logique de résumé relèvent de l'implémentation privée.

## Patterns courants

Utilisez la mémoire pour conserver du contexte durable :

- conventions de code ;
- décisions d'architecture toujours valides ;
- stratégie de tests préférée ;
- contraintes de déploiement ;
- terminologie d'équipe.

N'utilisez pas la mémoire pour :

- secrets ;
- notes temporaires ;
- décisions obsolètes ;
- données personnelles qui n'ont pas leur place dans le contexte d'ingénierie.

## Vue configuration

La mémoire peut être activée, désactivée ou encadrée par une politique d'équipe. Les équipes enterprise doivent définir en interne ce qui peut être lu, écrit et conservé.
