# Règles et templates

> Les conventions d'équipe doivent être explicites. NeuraForge permet de les exprimer sous forme de règles et de templates réutilisables.

## Règles enterprise

Les règles décrivent les standards que les agents doivent respecter dans votre dépôt.

Elles couvrent souvent :

- style de code ;
- attentes de tests ;
- contraintes sécurité ;
- conventions API ;
- exigences documentaires ;
- conventions de commit et pull request.

### Ajouter une règle

```bash
neuraforge rules add coding-standards.md
```

### Exemple de règle

```markdown
# Coding Standards

- Use strict typing.
- Add tests for business logic.
- Follow the team's commit convention.
- Do not expose secrets in generated artifacts.
```

Le modèle public reste volontairement simple : écrivez les attentes en langage clair et gardez-les avec le projet. L'assemblage exact des prompts et le filtrage relèvent de l'implémentation interne de NeuraForge.

## Templates

Les templates standardisent les artefacts : briefs, specs, reviews, change summaries et notes opérationnelles.

Utilisez-les lorsque votre équipe veut une documentation cohérente entre fonctionnalités et dépôts.

```bash
neuraforge template customize spec
```

Personnalisations fréquentes :

- ajouter une section impact GDPR ;
- exiger des notes de rollback ;
- inclure le transfert support ;
- formater les critères d'acceptation ;
- demander des ADR pour les gros changements.

## Bonne pratique

Gardez les règles publiques compréhensibles par les humains. Si une règle dépend d'un processus interne détaillé, conservez ce détail dans la documentation privée et exposez seulement l'attente opérationnelle dans le dépôt.
