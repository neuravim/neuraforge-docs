# Les 3 modes NeuraForge

> Bug fix → Flash. Feature → Standard. Migration critique → Enterprise. En cas de doute, commencez avec Standard.

NeuraForge adapte le workflow au risque et à la taille de la tâche. On n'a pas besoin du même processus pour une faute de frappe, une nouvelle API et une migration réglementée.

## Vue d'ensemble

| Besoin | Mode recommandé | Ce que vous obtenez |
|---|---|---|
| Correction ou petit changement | Flash | Implémentation rapide avec peu de cérémonie |
| Fonctionnalité produit classique | Standard | Analyse, plan, implémentation et revue |
| Travail sensible ou critique | Enterprise | Contrôles renforcés, validation humaine et documentation opérationnelle |

## Flash

Utilisez Flash quand le changement est petit, isolé et à faible risque.

```bash
neuraforge flash "Fix the broken health-check response"
```

Bon cas d'usage :

- faute de frappe ou petit bug ;
- refactoring simple ;
- périmètre limité ;
- pas d'impact majeur architecture ou sécurité.

## Standard

Utilisez Standard pour la majorité des travaux d'ingénierie courants.

```bash
neuraforge standard "Add a users API with tests"
```

Bon cas d'usage :

- nouvelle fonctionnalité ;
- intégration ;
- refactoring moyen ;
- travail qui bénéficie d'un plan et d'une revue.

Standard répond à un besoin simple : livrer une feature fiable sans transformer chaque ticket en programme de gouvernance. Le workflow garde ensemble l'analyse, le plan, l'implémentation, les tests, la revue sécurité et la QA, afin que l'équipe puisse vérifier que la demande produit est réellement devenue un changement exploitable.

## Enterprise

Utilisez Enterprise quand la qualité de livraison compte autant que la vitesse.

```bash
neuraforge enterprise "Migrate authentication to the new identity provider"
```

Bon cas d'usage :

- migration critique ;
- conformité ou sécurité ;
- changement avec impact production ;
- validation métier requise ;
- runbook, rollback et transfert support attendus.

Enterprise évite un problème fréquent des outils de code IA : confondre une réponse convaincante ou un prototype local avec un livrable réellement prêt pour la production.

## Standard vs Enterprise

La différence ne se limite pas aux agents activés. Elle concerne surtout le niveau de garantie attendu autour du livrable.

### Standard : feature maîtrisée

Standard convient quand vous voulez une livraison structurée dans un repo réel : analyse, plan, code, tests, revue et critères d'acceptation restent connectés. C'est le bon choix pour une API, une intégration, une évolution produit ou un refactoring qui doit être vérifié, sans exiger toute la gouvernance d'un changement critique.

### Enterprise : livraison gouvernée

Enterprise convient quand l'échec coûte cher : production, sécurité, conformité, migration, dette legacy ou validation métier. Ce mode ajoute les éléments attendus dans un contexte grand compte : documentation opérationnelle, runbook, logique de rollback, validation humaine, auditabilité et readiness production.

| Dimension | Standard | Enterprise |
|---|---|---|
| Objectif | Livrer une feature fiable | Livrer un changement critique et défendable |
| Cas typique | API, feature produit, intégration, refactoring moyen | Migration, authentification, sécurité, conformité, production |
| Documentation | Utile mais légère | Attendue : docs, runbook, rollback, transfert support |
| Validation humaine | Optionnelle selon l'équipe | Attendue ou obligatoire |
| Sécurité et QA | Revue standard et critères vérifiés | Contrôles renforcés et readiness production |
| Traçabilité | Artefacts de feature | Artefacts, décisions, validations et audit trail |
| Public cible | Équipe produit et engineering | CTO, sécurité, ops, compliance, grands comptes |

En résumé : **Standard** structure la livraison d'une feature sérieuse. **Enterprise** ajoute la gouvernance nécessaire quand la feature doit être exploitable, documentée, auditable et acceptable pour une organisation à fort niveau d'exigence.

## Changer de niveau quand le périmètre évolue

Si une tâche s'avère plus complexe que prévu, NeuraForge peut vous orienter vers un workflow plus robuste sans vous forcer à repartir de zéro. La logique exacte d'orchestration reste interne ; côté utilisateur, l'expérience reste simple : commencez avec la bonne intention, puis montez en niveau si le risque le justifie.
