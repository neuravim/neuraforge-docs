# CLI Reference

> This public reference lists the commands users need day to day. Internal execution details are intentionally not documented here.

## Workflow commands

### `neuraforge init`

Initializes NeuraForge in a repository.

```bash
neuraforge init
```

### `neuraforge flash <description>`

Runs a fast workflow for small changes.

```bash
neuraforge flash "Fix the broken health check"
```

### `neuraforge standard <description>`

Runs the normal workflow for feature work.

```bash
neuraforge standard "Add a users API with tests"
```

### `neuraforge enterprise <description>`

Runs the controlled workflow for sensitive or production-critical work.

```bash
neuraforge enterprise "Migrate authentication to the new provider"
```

Useful options:

- `--provider <name>`: choose a provider for the run;
- `--profile <name>`: use a domain profile;
- `--trace`: show more execution context for troubleshooting;
- `--dry-run`: preview the workflow without applying changes.

## Tracking commands

```bash
neuraforge status
neuraforge status <feature-slug>
neuraforge resume <feature-slug>
neuraforge abort <feature-slug>
```

Use these commands to inspect or continue work created by NeuraForge.

## Configuration commands

```bash
neuraforge config show
neuraforge config get provider
neuraforge config set mode standard
```

## Rules, templates and skills

```bash
neuraforge rules list
neuraforge rules add coding-standards.md
neuraforge template customize spec
neuraforge skills list
neuraforge skills install <skill-name>
```

## Provider commands

```bash
neuraforge providers list
neuraforge providers doctor
```

Use provider guides for installation and authentication details.

## Public/private boundary

The CLI exposes a simple user experience. The internal implementation of orchestration, prompt construction, provider routing, quality gates and artifact contracts is not part of this public reference.
