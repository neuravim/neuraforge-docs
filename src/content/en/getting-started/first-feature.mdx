# Your first feature in standard mode

> Standard mode is for real feature work: understand the request, plan the change, implement it, then verify the result.

This tutorial shows the public user experience without exposing NeuraForge's internal orchestration contracts.

## Scenario

Add a health-check endpoint to an existing API.

```bash
neuraforge standard "Add GET /health returning { status: 'ok' } with tests"
```

## What happens

NeuraForge guides the change through a structured delivery flow:

1. **Discovery** — understand the repository and the requested behavior.
2. **Planning** — define the expected change and acceptance criteria.
3. **Implementation** — update the code and tests.
4. **Review** — check that the result matches the intent and does not introduce obvious quality or security problems.

The exact internal artifacts and contracts are private implementation details. What matters to the user is that the work is traceable and reviewable.

## What you should inspect

After the workflow finishes, review:

- changed files;
- generated or updated tests;
- acceptance criteria coverage;
- security notes if any;
- final summary and next steps.

```bash
neuraforge status
```

Then run your normal project checks:

```bash
npm test
npm run build
```

Use the commands that apply to your stack.

## If the result is not good enough

You can refine the request or use a stronger workflow:

```bash
neuraforge standard "Improve the /health endpoint with readiness checks and tests"
```

For production-sensitive changes, use enterprise mode.
