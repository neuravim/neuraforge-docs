# Skills

> Skills let teams package reusable guidance for NeuraForge without changing the product.

## What is a skill?

A skill is a reusable package of team knowledge. It can describe how a domain should be handled, which standards matter, or what checks should be performed for a class of work.

Use skills when a simple project rule is not enough and your team wants a repeatable way to guide NeuraForge across multiple tasks.

## When to use skills

Good use cases:

- security review expectations;
- compliance guidance;
- migration playbooks;
- domain-specific engineering standards;
- documentation requirements;
- team onboarding conventions.

For a single coding convention, use a normal rule. For a full repeatable workflow, use a skill.

## How teams use skills

A typical team flow is:

1. identify a repeated type of work;
2. write the guidance once;
3. attach it to the relevant projects or workflows;
4. keep improving it as the team learns.

The internal manifest format, hook events, priority rules and prompt-injection details are private implementation details. Public users only need to know that skills are versioned, reusable and designed for team governance.

## Example use cases

| Skill | Purpose |
|---|---|
| API standards | Keep endpoint design consistent across services |
| Security checklist | Make common appsec expectations explicit |
| Migration playbook | Guide legacy modernization work |
| Documentation policy | Ensure important changes come with usable docs |

## Installing and managing skills

```bash
neuraforge skills list
neuraforge skills install <skill-name>
neuraforge skills enable <skill-name>
neuraforge skills disable <skill-name>
```

Your organization may provide an internal registry or a curated set of approved skills.
