# The NeuraForge agents

> NeuraForge coordinates a small team of specialized AI agents so a request is not treated as a one-shot prompt.

## What the agents do

NeuraForge separates work into clear responsibilities:

- **Lead**: understands the request, chooses the right level of workflow, and keeps the delivery focused.
- **Analyst**: studies the codebase and the requested change before implementation starts.
- **Planner**: turns the analysis into a practical plan, stories, and acceptance criteria.
- **Dev**: implements the change and prepares tests.
- **Security Reviewer**: looks for application-security risks and unsafe assumptions.
- **QA**: checks the result against the expected behavior and quality bar.
- **DocOps**: prepares operational documentation for enterprise-grade delivery.

The important point is not the number of agents. It is the separation of duties: analysis, planning, implementation, security, QA and documentation do not collapse into the same generic answer.

## How collaboration works

A NeuraForge workflow moves from understanding to implementation and verification. Each step builds on the previous one, so the final result keeps traceability from the original request to the delivered change.

Publicly, you can think of the process as:

1. understand the request and the repository;
2. choose the appropriate delivery mode;
3. prepare a plan when the task needs one;
4. implement the change;
5. review security and quality;
6. document the outcome when enterprise delivery requires it.

The internal contracts, prompt structure, data schemas and orchestration rules are part of NeuraForge's private implementation and are not required to use the product.

## Activation by mode

| Capability | Flash | Standard | Enterprise |
|---|---|---|---|
| Fast implementation | Yes | Yes | Yes |
| Analysis and planning | Light | Yes | Yes |
| Security and QA review | Light | Yes | Stronger |
| Human approval | No | Optional | Yes |
| Operational documentation | No | Optional | Yes |

## When to use each level

- Use **Flash** for small, low-risk changes.
- Use **Standard** for normal features, integrations and refactors.
- Use **Enterprise** for sensitive work: migrations, security, compliance, production readiness and stakeholder approval.

## Custom behavior

Teams can adapt NeuraForge with rules, providers and domain playbooks without changing the core product. For example, a migration team can specialize the workflow for WildFly to Spring Boot while keeping the same controlled delivery model.

See [Agent Profiles & Domain Playbooks](/en/guides/agent-profiles) for the public overview.
