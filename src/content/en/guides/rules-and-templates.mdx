# Rules and Templates

> Team conventions should be explicit. NeuraForge lets you express them as reusable rules and document templates.

## Enterprise rules

Rules describe standards that agents should respect when working in your repository.

Typical rules cover:

- coding style;
- test expectations;
- security constraints;
- API conventions;
- documentation requirements;
- commit and pull request expectations.

### Add a rule

```bash
neuraforge rules add coding-standards.md
```

### Example rule

```markdown
# Coding Standards

- Use strict typing.
- Add tests for business logic.
- Follow the team's commit convention.
- Do not expose secrets in generated artifacts.
```

The public model is intentionally simple: write the expectations in plain language and keep them with the project. The exact prompt assembly and filtering behavior are internal to NeuraForge.

## Templates

Templates help standardize artifacts such as briefs, specs, reviews, change summaries and operational notes.

Use templates when your team wants consistent documentation across features and repositories.

```bash
neuraforge template customize spec
```

Common customizations:

- add a GDPR impact section;
- require rollback notes;
- include support handover details;
- add acceptance criteria formatting;
- enforce architecture decision records for large changes.

## Best practice

Keep public project rules understandable by humans. If a rule requires detailed internal process, keep that detail in your private engineering documentation and expose only the operational expectation in the repo.
