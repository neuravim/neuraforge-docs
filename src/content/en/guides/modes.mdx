# The 3 NeuraForge modes

> Bug fix → Flash. Feature → Standard. Critical migration → Enterprise. When in doubt, start with Standard.

NeuraForge adapts the workflow to the risk and size of the task. You do not need the same process for a typo, a new API, and a regulated migration.

## At a glance

| Need | Recommended mode | What you get |
|---|---|---|
| Small fix or quick change | Flash | Fast implementation with minimal ceremony |
| Normal product feature | Standard | Analysis, plan, implementation and review |
| Sensitive or business-critical work | Enterprise | Stronger controls, human approval and operational documentation |

## Flash

Use Flash when the change is small, isolated and low risk.

```bash
neuraforge flash "Fix the broken health-check response"
```

Good fit:

- typo or small bug fix;
- simple refactor;
- limited scope;
- no major architecture or security impact.

## Standard

Use Standard for the majority of normal engineering work.

```bash
neuraforge standard "Add a users API with tests"
```

Good fit:

- new feature;
- integration;
- medium refactor;
- work that benefits from a plan and review.

## Enterprise

Use Enterprise when delivery quality matters as much as speed.

```bash
neuraforge enterprise "Migrate authentication to the new identity provider"
```

Good fit:

- critical migration;
- compliance or security-sensitive work;
- production-impacting change;
- stakeholder approval required;
- runbooks, rollback and support handover expected.

Enterprise mode is designed to avoid a common failure mode of AI coding tools: confusing a convincing answer or local prototype with a production-ready deliverable.

## Switching when the scope changes

If a task turns out to be more complex than expected, NeuraForge can guide you toward a stronger workflow rather than forcing you to restart from scratch. The exact orchestration logic is internal, but the user experience is simple: start with the right intent, then escalate when the risk justifies it.
