# Memory governance

> NeuraForge can use project and session context, but current repository state and the user's request always matter most.

## Why memory governance matters

AI tools become more useful when they remember context, but memory can also become stale. NeuraForge treats memory as guidance, not as a replacement for reading the actual codebase.

Memory helps with:

- recurring project conventions;
- previous architectural decisions;
- known constraints;
- team preferences;
- lessons learned from earlier work.

## Safe public model

NeuraForge separates context by scope and applies governance rules so old or sensitive information does not override the current task.

As a user, remember three principles:

1. the repository and explicit request are the source of truth;
2. memory should be checked before it is trusted;
3. sensitive information should not be copied into generated artifacts.

The exact internal memory schema, prompt sections, precedence rules and summarization behavior are private implementation details.

## Common patterns

Use memory to preserve durable, reusable context:

- coding conventions that apply across features;
- architecture decisions that are still valid;
- preferred test strategy;
- deployment constraints;
- team-specific terminology.

Do not use memory for:

- secrets;
- temporary task notes;
- stale decisions;
- personal data that does not belong in engineering context.

## Configuration overview

Memory can be enabled, disabled or governed by team policy. Enterprise teams should define what can be read, written and retained in their internal documentation.
