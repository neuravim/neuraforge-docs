# Configuration

> NeuraForge works with a small project configuration and lets teams add standards when they need them.

## Minimal configuration

For most projects, you only need to declare the project, preferred provider, mode and language.

```yaml
project: my-project
provider: claude-code
mode: standard
lang: en
```

This keeps setup lightweight while still allowing teams to grow into stronger governance later.

## Configuration levels

NeuraForge supports several levels of configuration so personal, project and enterprise preferences do not fight each other:

1. product defaults;
2. organization standards;
3. project settings;
4. feature-level adjustments;
5. command-line overrides.

The exact merge behavior and internal schema are implementation details. As a user, the rule is simple: local and explicit choices take priority over broad defaults.

## What you can customize

Publicly supported customization areas include:

- default AI provider;
- workflow mode;
- language for generated artifacts;
- team rules;
- provider preferences;
- budget and safety preferences;
- memory behavior;
- enterprise approval expectations.

## Enterprise configuration

Teams can define shared standards once and reuse them across repositories. Typical enterprise standards include:

- preferred provider;
- default workflow mode;
- approval expectations;
- security rules;
- test coverage targets;
- commit conventions;
- documentation requirements.

## Modify via CLI

```bash
neuraforge config set mode flash
neuraforge config show
```

Use the CLI for everyday configuration. Keep organization-wide standards in the internal team setup guide.
